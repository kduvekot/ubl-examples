Transport Execution Plan Request: Valdara Industries to Ferrano Rail Cargo

Document 2 of 8 in the flow Ore from the mine to the factory (domestic, Urvania) · Transport Execution Plan Request in the UBL 2.5 specification

From Valdara Industries to Ferrano Rail Cargo, under the Trade Accord's transaction Transport execution plan request.

← Order · all documents of the flow · Transport Execution Plan →

The manufacturer, as transport user, asks the rail carrier for wagons and a slot to move the ore from the mine to its siding.

The XML file is valid against the UBL 2.5 schemas and the world's code lists. Below, every value with its place in the document and the reason for it.

Values and their reasons

The document itself

  • UBLVersionID = 2.5
    The earliest version of UBL 2 that defines every element of the document, as UBLVersionID asks: computed from the published models of UBL 2.0 to 2.5; Party/AdditionalPartyIdentification first appears in UBL 2.5.
  • CustomizationID = urn:ubl-examples:world:trns:transport-execution-plan-request:1.0
    The specification the document follows, at each level it claims, chained with #compliant#: the Trade Accord's transaction "Transport execution plan request". Each has a public description on the world's pages.
  • ProfileID = urn:ubl-examples:world:profile:transport:1.0
    The Trade Accord's process profile the document belongs to: transport, a generic, versioned profile, not the flow.
  • ProfileExecutionID = 9900043010
    The collaboration this document belongs to: the ore train Valdara books with Ferrano Rail Cargo, from its request to the carrier's invoice. Valdara Industries started it and gave it this identifier, which every document of it repeats.
  • ID = 7000025806
    The transport user's request number.
  • VersionID = 1
    The first version of the request.
  • UUID = 1136675e-5400-5624-8e01-dc21b86cbdfe
    A universally unique identifier of the document, derived from its place in the world (UUID version 5), so it stays the same on every build.
  • IssueDate = 2026-03-03
    The day after the order: the buyer books the train it named in its order.
  • IssueTime = 09:24:00-01:00
    The time the sender's system issued the document, in the sender's local time, with its offset from UTC.
  • Note = Drek trir sezhul mir drek daz nintrek krir drek drunbaz. (languageID qau)
    The note in Urvanian, the sender's language: The transport asked for.
  • Note = The ore train from the mine siding to the factory. (languageID en-XU)
