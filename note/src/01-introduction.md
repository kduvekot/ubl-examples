# Introduction

## Purpose

UBL defines hundreds of document types and thousands of elements. Its
definitions say what an element means, but readers also need to see how
an element is used: with which value, in which context, and in relation to
the other documents in a business process.

This note describes a method for creating UBL example documents that show
exactly that. The examples form one coherent set: they share the same
organisations, products and timeline, and documents that belong together
refer to each other the way they would in real exchanges.

## Scope

The method covers:

- the fictional world in which the examples take place;
- how a value is chosen for an element, and how the reason for that choice
  is recorded;
- how examples are checked, within a document and across documents;
- how examples are reviewed and maintained over UBL versions.

The examples illustrate UBL. They do not define a profile, a customization
or a national implementation, and a value used in an example is never the
only valid value.

## Starting point

The example set starts from the sample documents that OASIS published with
each UBL 2.x release. Their history, from UBL 2.0 to UBL 2.5, is kept in the
repository, one document per commit.
