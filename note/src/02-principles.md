# Principles

## One fictional UBL world

All examples take place in the same fictional world: a set of
organisations that do all their business with UBL. Documents that belong
together, such as a catalogue, an order, a despatch advice and an invoice,
or the transport and customs documents for the same goods, tell one
consistent story.

## Universal, not tied to one region

The world includes business within one country, within a region and
between continents. No country, legal system or process is the default.
Where an example uses a country-specific identifier or rule, it is one
illustration among others, not the way UBL has to be used.

## Every value has a reason

For each element in each example, the reason for its value is recorded:
why the value fits the semantic meaning of the element, as defined by UBL,
in the context of that document and that business situation. The reason
refers to the UBL definition first. Country rules or a specific process
only appear as illustrations.

## Proven, not only plausible

Values are checked automatically:

- the document is valid against the UBL schemas and code lists;
- the document is consistent in itself, for example totals, dates and
  internal references;
- the documents are consistent with each other, for example parties,
  references between documents and quantities along a process.

## Open and reproducible

The world, the reasons, the checks and the history are kept in a public
repository. Anyone can follow how an example was made, reproduce it, reuse
it or challenge it.
