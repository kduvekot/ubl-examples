Abstract:

This note describes how a coherent set of UBL example documents is created and maintained: a fictional world of organisations that exchange UBL documents with each other, and for every value in every example the reason why it fits the semantic meaning of its element in that context.

1 Introduction

1.1 Purpose

UBL defines hundreds of document types and thousands of elements. Its definitions say what an element means, but readers also need to see how an element is used: with which value, in which context, and in relation to the other documents in a business process.

This note describes a method for creating UBL example documents that show exactly that. The examples form one coherent set: they share the same organisations, products and timeline, and documents that belong together refer to each other the way they would in real exchanges.

1.2 Scope

The method covers:

  • the fictional world in which the examples take place;

  • how a value is chosen for an element, and how the reason for that choice is recorded;

  • how examples are checked, within a document and across documents;

  • how examples are reviewed and maintained over UBL versions.

The examples illustrate UBL. They do not define a profile, a customization or a national implementation, and a value used in an example is never the only valid value.

1.3 Starting point

The example set starts from the sample documents that OASIS published with each UBL 2.x release. Their history, from UBL 2.0 to UBL 2.5, is kept in the repository, one document per commit.

2 Principles

2.1 One fictional UBL world

All examples take place in the same fictional world: a set of organisations that do all their business with UBL. Documents that belong together, such as a catalogue, an order, a despatch advice and an invoice, or the transport and customs documents for the same goods, tell one consistent story.

2.2 Universal, not tied to one region

The world includes business within one country, within a region and between continents. No country, legal system or process is the default. Where an example uses a country-specific identifier or rule, it is one illustration among others, not the way UBL has to be used.

2.3 Every value has a reason

For each element in each example, the reason for its value is recorded: why the value fits the semantic meaning of the element, as defined by UBL, in the context of that document and that business situation. The reason refers to the UBL definition first. Country rules or a specific process only appear as illustrations.

2.4 Proven, not only plausible

Values are checked automatically:

  • the document is valid against the UBL schemas and code lists;

  • the document is consistent in itself, for example totals, dates and internal references;

  • the documents are consistent with each other, for example parties, references between documents and quantities along a process.

2.5 Open and reproducible

The world, the reasons, the checks and the history are kept in a public repository. Anyone can follow how an example was made, reproduce it, reuse it or challenge it.
