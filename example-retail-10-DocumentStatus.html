Document Status: Lumeway Distribution to Brightmarket Stores

Example 10 of the flow "Distributor to retailer, delivered duty paid (domestic, Bayvarra)" · Document Status in the UBL 2.5 specification

The distributor answers: confirmed, the truck is booked.

The XML file is valid against the UBL 2.5 schemas and the world's code lists. Below, every value with its place in the document and the reason for it.

Values and their reasons

The document itself

  • UBLVersionID = 2.5
    The earliest version of UBL 2 that defines every element of the document, as UBLVersionID asks: computed from the published models of UBL 2.0 to 2.5 (world/ubl-versions.json); Party/AdditionalPartyIdentification first appears in UBL 2.5.
  • CustomizationID = urn:ubl-examples:world:trns:order-status:1.0#compliant#urn:ubl-examples:world:community:retail:1.0
    The specification the document follows, at each level it claims, chained with #compliant#: the Trade Accord's transaction "Order status"; the community specification "Retail community". Each has a public description on the world's pages (world/specifications.json).
  • ProfileID = urn:ubl-examples:world:profile:ordering:1.0
    The Trade Accord's process profile the document belongs to: ordering, a generic, versioned profile, not the flow; the run of the process is the ProfileExecutionID.
  • ProfileExecutionID = RETAIL-2026-01
    This run of the process: the same in every document of the flow.
  • ID = LD-DOC-26-0226
    The sender's number for this document.
  • UUID = eb9072fe-2cf3-54f8-bb18-08f7f9930b9c
    A universally unique identifier of the document, derived from its place in the world (UUID version 5), so it stays the same on every build.
  • IssueDate = 2026-04-26
    Answered the same day.
  • IssueTime = 11:14:00-01:00
    The time the sender's system issued the document, in the sender's local time; in the issuer's local time, with its offset from UTC (D27).
  • Note = Accepted and booked.
    The answer.

Signature

Inside Signature:

  • ID = LD-SIG-26-DS
    The sender's electronic seal.
  • SignatoryParty/PartyIdentification/ID = 20410274 (schemeID urn:ubl-examples:world:XB:register)
    A party referred to from another party's details: its identifier and name are enough.
  • SignatoryParty/PartyName/Name = Lumeway Distribution
    A party referred to from another party's details: its identifier and name are enough.

Sender Party

Inside SenderParty:

  • PartyIdentification/ID = 20410274 (schemeID urn:ubl-examples:world:XB:register)
    The party's preferred identifier: its number in the Federal business register of Bayvarra; identity of Lumeway Distribution (world/parties.json). Later mentions of the same party in this document repeat only this identifier and the name.
  • AdditionalPartyIdentification/ID = 9520610900008 (schemeID GS1 GLN)
    A further identifier, the party's Global Location Number (the endorsed PartyIdentification holds one only): it identifies itself, its items and its places the GS1 way, under its company prefix, which starts with 952, the prefix GS1 reserves for examples (decision ID-Q7); identity of Lumeway Distribution (world/parties.json).
  • PartyName/Name = Lumeway Distribution
    The trading name; identity of Lumeway Distribution (world/parties.json).
  • Language/ID = en (schemeID ISO 639)
    English, the language the party writes in this document. The code is from the world's copy of ISO 639 Language: en = English. An identifier that holds a code names the code's list in its schemeID.
  • Language/Name = English
    The language's name.
  • Language/LocaleCode = en-XB (listID urn:ubl-examples:world:codelist:LocaleCode)
    The English the party writes: the variety of Bayvarra, with the country as the region; English is used in all three countries, so its locale says which (decision D1). The code is from the Trade Accord's locale list: en-XB = Bayvarran English.
  • Contact/Name = Sales office
    The party's sales office desk: the desk for its role in this document (it sells); identity of Lumeway Distribution (world/parties.json).
  • Contact/JobTitle = Sales coordinator
    The job of the person who answers at the desk; identity of Lumeway Distribution (world/parties.json).
  • Contact/Department = Sales
    The department the desk belongs to; identity of Lumeway Distribution (world/parties.json).
  • Contact/Telephone = +999 2 7121 955 964
    The party's switchboard, which puts the caller through to the desk. Telephone under +999, a country code the ITU reserves for a future global service (ITU-T E.164), so the number reaches no one; then the country digit and a number in Bayvarra's own plan: British-style closed numbering: always 10 digits after the country digit; the area code takes 2 to 5 of them (Lumeport 38, Upland State 7121, Gullhaven 38522 in the Northern Territory: the plan is national and does not follow state borders) and the trunk prefix 0 is dropped from abroad. Mobiles start with 7. identity of Lumeway Distribution (world/parties.json).
  • Contact/ElectronicMail = sales@lumeway.example
    E-mail under the reserved .example domain (RFC 2606), so it cannot reach anyone; identity of Lumeway Distribution (world/parties.json).
  • Contact/Note = Weekdays 08:00–17:00
    When the desk can be reached; identity of Lumeway Distribution (world/parties.json).
  • ElectronicAddress/ExchangeNetworkID = urn:ubl-examples:world:network
    The network in which the address is registered: the world's own exchange network.
  • ElectronicAddress/ElectronicAddressID = XB:20410274 (schemeID urn:ubl-examples:world:endpoint)
    The party's electronic address in that network: its country code and registry number; identity of Lumeway Distribution (world/parties.json). UBL 2.5 carries it here; Party/EndpointID is deprecated.

Document Response

Inside DocumentResponse:

  • Response/ResponseCode = AP (listID UN/EDIFACT EDED 4343)
    UN/EDIFACT 4343 code AP: the order is accepted and the truck is booked. The code is from the world's copy of UN/EDIFACT 4343 Response type: AP = Accepted.
  • DocumentReference/ID = BS-PO-26-0224
    The order the status is about.
  • DocumentReference/DocumentTypeCode = Order (listID urn:ubl-examples:world:codelist:UBLDocumentTypeCode)
    The kind of document referred to: BS-PO-26-0224 is the example retail/08, a Order; a generic reference names the UBL document type (decision Q29). The code is from the Trade Accord's UBL document type list: Order.
