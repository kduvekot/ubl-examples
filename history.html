History of the OASIS UBL sample documents

The xml/ folder of this repository holds the sample documents that OASIS published with UBL 2.0 up to UBL 2.5. Its git history is rebuilt from the published sources: you can see when each example was added, changed or removed, as if the examples had been maintained here from the start. UBL 1.0 is out of scope.

Sources

  1. docs.oasis-open.org. Every UBL 2.x stage directory with an xml/ folder: https://docs.oasis-open.org/ubl/. tools/crawl_oasis.py downloads every file and records it in manifest.json (path, size, server timestamp, SHA-256).
  2. github.com/oasis-tcs/ubl. The TC's working repository. It starts in May 2021 (a copy of 2.3 CSD05). Only 12 of its commits touch the examples (raw/xml/). They give finer detail for two stages: intermediate versions of Invoice-2.1, PurchaseReceipt-2.4 and DebitNote-2.5, plus who removed DebitNote-2.1 and FreightInvoice-2.1, and when.

How the history is built

  • Starting commit. The history starts on 17 October 2001, when OASIS announced the formation of the UBL Technical Committee (press release). The proposal was submitted on 28 August 2001; the first meeting was held the week of 29 October 2001, hosted by Sun Microsystems (Cover Pages). This commit only adds README.md.
  • One document per commit. Each commit adds, updates or removes exactly one file in xml/.
  • Published changes are dated on the stage's publication date (12:00 UTC) and authored by "OASIS UBL TC". The commit message names the stage, the source URL and the SHA-256 of the published file.
  • Changes from the OASIS GitHub repository keep the original author, date and message, with a link to the source commit. Versions that never appeared on docs.oasis-open.org are marked intermediate.
  • Every stage ends with a release commit, also when it changed nothing. That commit adds the stage's release notes (added, updated and removed files) to README.md. It gets an annotated tag with the stage's directory name (e.g. os-UBL-2.1), and its xml/ folder equals what the stage published, byte for byte; the build stops if it doesn't.
  • Stage order and date come from the server timestamps of the published files. Exception: os-UBL-2.0-update republished the 2006 files unchanged and is dated on its publication date, 2008-05-29.
  • Deterministic. The same manifest, cache and GitHub clone always give the same commit hashes. The published branch was built with --committer "Claude <noreply@anthropic.com>" --sign, so its commits are signed and their hashes depend on the signing key. Authors, dates, messages and file contents are the same as in an unsigned build, so you can compare with git diff or by tree hash (git log --format=%T).

Reproduce

python3 tools/crawl_oasis.py --cache /path/to/cache --out history/manifest.json
git clone --filter=blob:none --no-checkout https://github.com/oasis-tcs/ubl.git /path/to/oasis-ubl
python3 tools/build_history.py --cache /path/to/cache --oasis-repo /path/to/oasis-ubl --repo . --branch examples-history

Re-running the crawl and comparing manifest.json (git diff) shows whether anything was published or changed on docs.oasis-open.org since the last crawl.

In total there are 189 published document changes (82 added, 101 updated, 6 removed) and 6 intermediate versions from GitHub: 195 document commits. With the starting commit and the 36 release commits, the rebuilt history has 232 commits. The commits adding this tooling come on top.

Relation to earlier attempts

The branches claude/ubl-samples-hist-3IuwR and sample-research (official/) held partial copies: only changed files, and no CS/COS/OS stages. Every file version on those branches is part of this history.
